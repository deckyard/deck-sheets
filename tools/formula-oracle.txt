# Formulas cross-checked against LibreOffice and Gnumeric by
# tools/formula-oracle.sh. One formula per line, in A1 notation and without a
# leading `=`. Lines starting with `#` and blank lines are ignored.
#
# The fixture the formulas see is fixed in tools/formula-oracle.j:
#
#   A1=4  B1=2  C1=9.99  D1="beta"  E1=blank
#   A2=TRUE  B2=FALSE  C2=-7  D2="Beta"  E2=1
#   A3=1  B3=2  C3=3  D3=4  E3=5
#
# Keep a formula out of here when its answer is not stable across
# applications: a locale-dependent VALUE(), anything built on TODAY(), or a
# display format rather than a value. Three cases were pulled for that reason
# and are covered by the test overlays instead:
#
#   D1="BETA"           this LibreOffice compares text case-sensitively while
#                       Gnumeric and Excel do not. The engine follows the
#                       majority and is case-insensitive.
#   CONCAT(D1,"-",D2)   Gnumeric and Excel have CONCAT; this LibreOffice
#                       answers #NAME?.
#   VALUE("12.5")       Gnumeric reads the decimal separator from the locale.
#   QUOTIENT(1,0)       the two applications disagree: Gnumeric and Excel say
#                       #DIV/0!, this LibreOffice says #NUM!. The engine
#                       follows the majority.
#   COUNT(A2:E2)        Gnumeric and Excel skip booleans held in cells, this
#                       LibreOffice counts them. The engine follows the
#                       majority; see testCountSkipsBooleansInASpan.
#   VLOOKUP(...,9,...)  a column index past the range is #REF! in Gnumeric and
#                       Excel, #NUM! in this LibreOffice.
#   MATCH(3,A3:E3,-1)   a descending search over ascending data is undefined,
#                       and the two applications give different answers.
#   TEXT(0,"#.##")      zero through a format whose every placeholder is
#                       optional leaves just the point. Gnumeric and Excel
#                       show ".", this LibreOffice shows nothing.
#   TEXT(x,"hh:mm:ss")  a serial with a fractional second: Gnumeric rounds it
#                       to the nearest second and this LibreOffice truncates.
#                       The engine rounds - truncating would make TEXT(1/3,
#                       "hh:mm:ss") 07:59:59, which disagrees with both.
#   TEXT(-12.5,"yyyy-  a negative serial is not a date. Both applications
#   mm-dd")             render one anyway, counting backwards from the origin,
#                       and they disagree about which day it is (1899-12-17
#                       against 1899-12-18). The engine shows the number.
#   TEXT(2.25,"yyyy-   a serial below 61 falls either side of the 1900 leap
#   mm-dd")             bug: Excel and Gnumeric count 1900-01-02, this
#                       LibreOffice 1900-01-01. See docs/guide/model.md.
